# SCHEMA 

## NOTATION AND DESCRIPTION:

Below is a description of the node and edge types used to define the schema of the graph.

Note: The notation below follows closely with Neo4J CYPHER syntax.

### Node Types:

* :CLASS
  * Definition: Defines a category or type
  * Properties:
    * name: name of the class
    * description: description of the class
  * Example: PERSON, COMPANY

* :RELATION
  * Definition: Defines the nature of a relationship between two entity classes
  * Properties:
    * name: name of the relation
    * description: description of the relation
    * is_symmetric: boolean indicating symmetry
  * Example: WORKED_AT, LIVES_IN, PURCHASED

* :PROPERTY
  * Definition: Feature of an entity, class, relation, or fact
  * Properties:
    * name: name of the property
    * description: description of the property
  * Example: AGE, START_DATE

* :FACT
  * Definition: Represents a specific factual relation between entities
  * Properties: NONE
  * Example: Alice_WORKED_AT_IBM

* :ENTITY
  * Definition: A specific instance of a class
  * Properties:
    * id: unique id of an entity
  * Example: Alice, IBM

* :LITERAL
  * Definition: Specifies a property value
  * Properties:
    * value: value of the property
    * type: NUMBER or DATE or BOOLEAN or STRING
  * Example: 18, 1998

* :SOURCE
  * Definition: A source of data
  * Properties:
    * id: id of the source
    * name: name of the source
    * description: description of the source

* :EXTRACTION
  * Definition: Extraction from a source
  * Properties:
    * text: text segment of extraction from source

---

### Edge Types:


* :IS_SUBCLASS_OF
  * Definition: Defines hierarchical inheritance between two schema elements. The child inherits properties and semantics from the parent.
  * From: :CLASS or :RELATION
  * To: :CLASS or :RELATION
  * Example: EMPLOYEE IS_SUBCLASS_OF PERSON

* :IS_INSTANCE_OF
  * Definition: Connects a specific entity to a class, asserting that the entity is a concrete realization of that class.
  * From: :ENTITY
  * To: :CLASS
  * Example: IBM IS_INSTANCE_OF COMPANY

* :DEFINE_PROPERTY
  * Definition: Declares that a class or relation has a given property in its schema definition.
  * From: :CLASS or :RELATION
  * To: :PROPERTY
  * Example: PERSON DEFINE_PROPERTY AGE


* :IS_VALUE_OF
  * Definition: Links a literal value to the property it instantiates.
  * From: :LITERAL
  * To: :PROPERTY
  * Example: 18 IS_VALUE_OF AGE

* :HAS_PROPERTY
  * Definition: Assigns a literal value or attribute to an entity or fact instance.
  * From: :ENTITY or :FACT
  * To: :LITERAL
  * Example: Alice HAS_PROPERTY 28

* :REPRESENTS
  * Definition: Connects a fact instance to the relation type it instantiates, grounding the fact in schema semantics.
  * From: :FACT
  * To: :RELATION
  * Example: Alice_WORKED_AT_IBM REPRESENTS WORKED_AT

* :HEAD
  * Definition: Specifies the subject (from) entity of a fact.
  * From: :FACT
  * To: :ENTITY
  * Example: FACT → Alice

* :TAIL
  * Definition: Specifies the object (to) entity of a fact.
  * From: :FACT
  * To: :ENTITY
  * Example: FACT → IBM

* :DOMAIN
  * Definition: Declares the valid source class of a relation (what type of entity can appear in HEAD position).
  * From: :RELATION
  * To: :CLASS
  * Example: WORKED_AT DOMAIN EMPLOYEE


* :RANGE
  * Definition: Declares the valid target class of a relation (what type of entity can appear in TAIL position).
  * From: :RELATION
  * To: :CLASS
  * Example: WORKED_AT RANGE ORGANIZATION


* :EXTRACTED_FROM
  * Definition: Links any schema element (entity, fact, or literal) to its originating extraction record or source evidence.
  * From: :ENTITY or :LITERAL or :FACT
  * To: :EXTRACTION
  * Example: Alice WORKED_AT IBM EXTRACTED_FROM Resume_Text_1


# SCHEMA

## BASE ENTITIES

(person:CLASS {name: 'PERSON', description: 'Human individual'})
(user:CLASS {name: 'USER', description: 'Digital user profile extending PERSON'})
(user)-[:IS_SUBCLASS_OF]->(person)

(employee:CLASS {name: 'EMPLOYEE', description: 'Person employed by an organization'})
(employee)-[:IS_SUBCLASS_OF]->(person)

(company:CLASS {name: 'COMPANY', description: 'For-profit organization'})
(organization:CLASS {name: 'ORGANIZATION', description: 'General organization'})

(company)-[:IS_SUBCLASS_OF]->(organization)

---

## DEMOGRAPHICS & IDENTITY

(demographic:CLASS {name: 'DEMOGRAPHIC_PROFILE', description: 'User demographic attributes'})
(location:CLASS {name: 'LOCATION', description: 'Geographic location'})
(city:CLASS {name: 'CITY', description: 'City-level location'})
(country:CLASS {name: 'COUNTRY', description: 'Country-level location'})

(city)-[:IS_SUBCLASS_OF]->(location)
(country)-[:IS_SUBCLASS_OF]->(location)

(gender:PROPERTY {name: 'GENDER', description: 'Gender identity'})
(dob:PROPERTY {name: 'DATE_OF_BIRTH', description: 'Birth date'})
(nationality:PROPERTY {name: 'NATIONALITY', description: 'Nationality'})
(age:PROPERTY {name: 'AGE', description: 'Age in years'})

(user)-[:DEFINE_PROPERTY]->(gender)
(user)-[:DEFINE_PROPERTY]->(dob)
(user)-[:DEFINE_PROPERTY]->(nationality)
(user)-[:DEFINE_PROPERTY]->(age)

(has_demographics:RELATION {name: 'HAS_DEMOGRAPHICS', description: 'Links user to demographic profile', is_symmetric: false})
(has_demographics)-[:DOMAIN]->(user)
(has_demographics)-[:RANGE]->(demographic)

(lives_in:RELATION {name: 'LIVES_IN', description: 'Residence location', is_symmetric: false})
(lives_in)-[:DOMAIN]->(person)
(lives_in)-[:RANGE]->(location)

(born_in:RELATION {name: 'BORN_IN', description: 'Birth location', is_symmetric: false})
(born_in)-[:DOMAIN]->(person)
(born_in)-[:RANGE]->(location)
